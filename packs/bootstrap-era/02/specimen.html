The chronoskin API

Rooms, people and bookings over plain HTTP. Add scheduling to your own application with a handful of calls and a library for the language you already write.

Scheduling, without writing a calendar.

chronoskin keeps the calendar and its rules. Your application asks what is free, books it, and hears about every change.

Bookings

Create, move and cancel a booking with one request each. Clashes are refused with a reason your code can read.

View details »

Availability

Ask for free slots by room, person or both. Opening hours, breaks and time zones are worked out on our side.

View details »

Webhooks

Name an address and we post to it whenever a booking is made, moved or cancelled, with retries for a day.

Your first booking

Every call is an HTTPS request that answers in JSON.

You need an API key, which you send as the user name of each request. Keys come in two kinds: a test key that books nothing real, and a live key.

Find a free slot

Ask a room for its free slots on a day. Times come back in the time zone of the room, in steps set by slot_minutes.

  • curl
  • Ruby
  • Python
  • PHP
# free slots in room 14 on 16 September
$ curl api.chronoskin.example/v2/rooms/14/free \
    -u YOUR_KEY: \
    -d day=2013-09-16

Test keys are safe. A booking made with a test key is kept for an hour and never reaches a calendar.

Do not ship a live key in a web page. Anyone who reads the page source can book with it. Call the API from your server.

Book it

Post the slot back with the name of whoever it is for. The answer carries the booking and its address.

  • A slot that has gone answers 409 with the nearest free time
  • A room that is closed answers 422 with the opening hours
  • Too many calls answer 429; wait and send it again

What to read next

Bookings can repeat, belong to several people and tell your server when they change. The reference has every field.

POST /bookings Stable

Books a free slot in one room. Send room, start and name; the length defaults to one slot.

{
  "id": 90211,
  "room": 14,
  "start": "2013-09-16T09:30:00+02:00",
  "name": "Design review"
}
Answers 201 with the booking, or 409 when the slot has gone.

When it does not answer 201

409: the slot has gone

Somebody else booked it first. The answer carries the nearest free time, so you can offer it straight away.

422: the room is closed

The start lies outside the opening hours of the room. The answer lists them.

429: too many calls

Wait for the number of seconds in the Retry-After header and send the call again.
