  3. 09:12 UTCInvestigating

Postmortem

Draft

A replica that could not keep up

A schema change rewrote a large table, and one replica applied it more slowly than the others.

The router sends reads to any replica less than max_lag behind. That setting was 120 seconds, so a replica 90 seconds behind still took traffic.

What we are changing

  • The default for max_lag drops to 10 seconds
  • Schema changes on tables over 50 GB are throttled per replica
  • A new alert fires when any replica is behind for more than a minute

What you need to do

Nothing. The new default applies to every project from 20 March.

Affected components

  • Query engine, fra1 degraded
  • API gateway normal
  • Storage normal
  • Dashboard normal
