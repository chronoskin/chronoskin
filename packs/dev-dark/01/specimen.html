Fig. 01 / the pipeline

One pipeline from push to production. Previews, checks, regions and rollbacks are the same few lines of configuration.

A preview for every branch

Each push gets its own address with its own environment. Reviewers open a link, not a terminal.

Nineteen regions

Name the regions in one line. Traffic goes to the nearest healthy one.

Checks that block

Tests, type checks and your own scripts run before anything is promoted.

Logs and timings

Every request, build step and cold start, kept for thirty days and searchable.

Rollback in one step

Any earlier deployment is still there. Point production back at it in a second.

12 Mar 2025New

Instant rollbacks

Production can now point at any earlier deployment without a rebuild.

Every deployment is kept as built. A rollback only moves the production address, so it takes about one second in every region.

What changed

  • A rollback button on every deployment that was once in production
  • Automatic rollback when the error rate passes a limit you set
  • The audit log records who rolled back, and from where

From the command line

Run chronoskin rollback to go back one step, or pass a deployment id to pick one.

27 Feb 2025Faster

Build cache is shared across branches

A new branch starts from the cache of the branch it was cut from. Cold builds are 40% faster on average.

terminalbefore / after
# feat/usage-export, first build
build  1m 04s   cache miss
build     38s   cache from main

Nothing to switch on. To opt a branch out, set cache: false.
